# 脚本导航

`tool-download.ps1` 供 Trivy/age 共用，以 HTTP/1.1 访问同一 GitHub 资产的 `?download=1` 入口：仅对 HTTP 502/503/504 最多请求三次（每次 120 秒超时、间隔 2 秒），验证固定 SHA-256 后才发布工具归档；损坏的既有缓存不覆盖。真实本机 HTTP 回归入口为 `pwsh -NoProfile -File scripts/tests/test-tool-download.ps1`，不访问外部下载站点。

开发静态图片回归：`node --test scripts/demo-images.test.mjs` 使用独立的 `127.0.0.1:15173/15174` 端口启动两端开发服务器，验证共享 SVG 的 GET、HEAD 与缺失资源行为，不访问后端。生产静态路由回归：`pwsh -NoProfile -File scripts/tests/test-production-static.ps1 -WebImage <已构建的Web镜像>` 使用随机本机端口和临时 Nginx 容器，不挂载业务数据，结束后退出并回收临时配置。

GHCR 分发由 `.github/workflows/publish-images.yml` 手动触发，内部调用 `publish-images.ps1`，输入精确来源、成功 run、清单摘要与版本。它校验已发布 Release 与对应源码附件，拒绝覆盖已有标签，再推广同一已测试镜像并拉回核对 config/diff IDs。`collect-image-sources.py` 使用 Python 3.11+，按实际应用镜像采集对应源码和通知；内容随 `runtime-sources.tar.gz` 交付。发布编排回归入口为 `scripts/tests/test-publish-images.ps1`。

以下脚本从项目根目录执行，PowerShell 脚本使用 `pwsh`。首次体验只需 `start.ps1 -SkipVerify`；其它脚本按需使用。环境配置、凭据、备份与输出保存在受忽略的 `.env`／`.local/`。

| 用途               | 脚本                                                                     | 说明                                                                                                                                                                                                                                           |
| ------------------ | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 首次启动、源码升级 | `start.ps1`                                                              | 生成本机配置、构建镜像并等待健康；已有数据会先暂停写入、备份和独立验证，详见[升级说明](../docs/platform-deployment.md)                                                                                                                         |
| CI制品下载         | `download-release.ps1`                                                   | 4 MiB有界分段，核对成功run、来源SHA及完整归档／清单摘要，不保存GitHub令牌                                                                                                                                                                      |
| CI制品发布         | `release.ps1`                                                            | 不构建镜像；停写迁移、原字段及上传核对、独立恢复后开放；应用发布保留已就绪依赖及业务卷，V4要求MySQL／Redis与制品身份一致，依赖补丁升级步骤见[部署说明](../docs/platform-deployment.md#已采用-ci-制品的日常环境)                                |
| CI制品导出         | `export-release.ps1`                                                     | CI末尾以V4清单导出已测试、扫描的Java／Web／MySQL／Redis四个镜像、四服务扫描证据、SBOM及来源；V1／V2两个应用镜像及V3三个镜像的历史验证格式仍保留                                                                                                |
| 加密副本与解密     | `encrypted-backups.ps1`、`decrypt-backup.ps1`                            | 固定age，缺公钥拒绝对外副本；私钥单独保管                                                                                                                                                                                                      |
| 调度预览           | `ops-schedule.ps1`                                                       | 生成和校验Windows任务XML，不实际注册                                                                                                                                                                                                           |
| 凭据权限           | `secure-files.ps1`                                                       | 写前限制权限并核验，失败中止；普通临时文件使用回收站清理                                                                                                                                                                                       |
| 制品身份核验       | `image-identity.ps1`                                                     | 发布内部辅助：验证 OCI 内容图、配置、平台清单及实际运行身份                                                                                                                                                                                    |
| 前端源码构建       | `build-frontends.ps1`                                                    | 安装依赖，检查兼容层和类型，构建管理端、H5、小程序                                                                                                                                                                                             |
| 小程序生产构建     | `build-mini-program.mjs`                                                 | 由客户端 `build:mp-weixin:production` 调用，读取进程环境中的真实 AppID/HTTPS 源并生成配置，见[接入说明](../docs/production-readiness.md#小程序生产构建)                                                                                        |
| 生产配置预检       | `production-preflight.ps1`                                               | 检查镜像摘要、HTTPS、双 Redis 隔离及恢复证据；云端连通与资金验收步骤见[生产部署](../docs/production-deployment.md)                                                                                                                             |
| 双节点验收         | `verify-cluster.ps1`、`check-multi-instance.mjs`                         | 在隔离项目验证会话、目录、票据、广播、幂等与节点停止恢复，使用模拟支付与独立数据                                                                                                                                                               |
| 基础可用性         | `smoke.ps1`                                                              | HTTP 就绪与入口检查                                                                                                                                                                                                                            |
| 运维只读检查       | `ops-check.ps1`                                                          | 任务、积压、图片、空间及验证备份；发现异常返回非零                                                                                                                                                                                             |
| 一次性运维入口     | `ops-run.ps1 -Action Check\|Backup`                                      | 可接定时调用，项目互斥；按配置复制验证备份、发送变化或恢复通知；不会自动注册定时任务                                                                                                                                                           |
| 运维接入模板       | [`../deploy/ops-config.example.json`](../deploy/ops-config.example.json) | 复制到 `.local/ops-config.json` 配置受控副本目录与告警地址；配置与状态不提交 Git                                                                                                                                                               |
| 安全备份           | `safe-backup.ps1`                                                        | 明确执行人工备份或发布验证时暂停写入并独立恢复检查，之后恢复原运行状态；当前本机不启用日常备份                                                                                                                                                 |
| 备份底层步骤       | `backup.ps1`                                                             | 导出数据库、文件与清单；单独运行不等同于完整安全备份流程                                                                                                                                                                                       |
| 独立恢复核验       | `restore-check.ps1`                                                      | 读取指定备份，在临时容器恢复并核验，不覆盖日常数据库                                                                                                                                                                                           |
| 历史库迁移预检     | `migration-preflight.ps1`                                                | 检查重复标识与归属；完整 schema 另行人工对照迁移基线                                                                                                                                                                                           |
| 数据清单比对       | `platform-data-manifest.ps1`                                             | 输出／比对指定业务数据清单，仅写入受保护的 `.local/`                                                                                                                                                                                           |
| 历史容器整理       | `consolidate-containers.ps1`                                             | 专项维护工具；先验证备份，仅处理匹配项目目录且已停止的旧容器，保留卷和镜像；首次部署无需执行                                                                                                                                                   |
| 接口类型           | `generate-contracts.mjs`                                                 | 默认从已有快照生成；`--fetch` 会登录指定后端并刷新快照                                                                                                                                                                                         |
| 通知验收           | `check-websocket.mjs`                                                    | 连接实际后端校验票据与会话边界，需要正确环境                                                                                                                                                                                                   |
| 用户端依赖审计     | `check-client-audit.mjs`                                                 | 检查 `.local/audit-client.json`，发现漏洞或无效报告即失败                                                                                                                                                                                      |
| 后端与镜像安全     | `scan-images.ps1`                                                        | 固定版本Trivy，扫描应用镜像及显式指定的MySQL／Redis镜像系统包、Java运行依赖；任意已知漏洞阻断，保留完整报告和CycloneDX清单                                                                                                                     |
| 性能身份与历史夹具 | `prepare-performance.mjs`                                                | 核验隔离项目、端口及卷；`--lunch` 增加3名热店员工会话，`--grow-history --history-orders` 将同一夹具递增至最多20万笔合成历史；`--refresh-sessions --source <原私有会话> --output <新文件>` 校验并重新鉴权同30用户/3店员，保留历史，不测登录容量 |
| 有限性能测量       | `measure-performance.mjs`                                                | 默认测量1／5／10／30客户端读取及30客户端混合交易；`PERF_SCENARIO=lunch` 测量30用户三波集中交易与历史／对账读取，操作说明见运维指南                                                                                                             |

`docker-read.ps1` 为运维命令提供带超时的 Docker 读取。制品下载入口调用 `github-artifact-transfer.ps1` 分段传输，并校验完整制品。
签名存储地址返回401/403时，在原15分钟预算内最多向同一GitHub artifact刷新两次，仅续传本次调用已确认的前缀；未知旧文件仍拒绝续传。

PowerShell 回归测试与夹具集中在 [tests/](tests/)。例如，从项目根目录运行 `pwsh -NoProfile -File ./scripts/tests/test-release-safety.ps1` 验证发布时的写入隔离。镜像身份与制品分段传输分别由 `tests/test-image-identity.ps1` 和 `tests/test-github-artifact-transfer.ps1` 在 Windows、Linux 两端验证。Node.js 脚本的测试以 `.test.mjs` 结尾，与被测脚本同目录。

涉及写入的业务、迁移和浏览器验收应使用独立项目、端口与数据卷。[日常维护](../docs/operations.md)列出备份与检查命令；完整自动验证入口是 [GitHub Actions](../.github/workflows/verify.yml)。

本机完整备份、离线镜像恢复包与自动备份保持停用，恢复指针为 `DISABLED_BY_USER`。当前仅保留工具与回执；人工发布时生成临时校验材料并更新 LATEST。成功后须由维护者按[部署保留策略](../docs/platform-deployment.md#本机保留策略)回收并恢复禁用标记，发布脚本不会自动完成清理。
