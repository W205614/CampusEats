# CampusEats · 校园多校区点餐平台

CampusEats 面向校园内多家餐饮店，提供用户点餐、商家接单、校区配送与售后管理。用户可以跨店、跨校区合并结算，各店独立备餐，按店选择配送或到店自取。

基于 **Java 21 / Spring Boot 4.1 + Vue 3 / TypeScript + uni-app + MySQL 8.4 + Redis 7.4**，采用单体、单实例后端，通过 Docker Compose 启动 MySQL、Redis、Java 后端和 Nginx 四个服务。

> 默认提供演示登录、模拟支付和模拟退款，不发生真实资金交易。适合本地体验和学习；微信小程序登录需要另行配置，尚未完成微信真机验收。不包含真实商户资金清算、自动路线规划或第三方配送。

本项目定位为个人可维护的单机、单实例演示应用，默认只监听本机。演示编号由访问者共享，请勿填写真实姓名、电话或地址；模拟支付成功不能作为真实收款凭证。外部身份核验、公网 HTTPS、高可用、异机灾备及常驻运维调度不属于已交付能力。

项目提供平台创建的独立测试账号：首次登录须改密，支持停用、密码重置和旧会话撤销。履约时限与异常工作台、配送交接、可离线补读的站内消息，以及模拟流水、日结和对账均已部署。支付、退款交互保持原有模拟方式。

项目进入按需维护阶段，源码最新迁移为 **V19**，已补充历史对账的聚合复用和覆盖索引。已有日常环境使用通过完整 CI 的制品；版本、容量测量与部署状态见[验证范围与最近结果](#验证范围与最近结果)。本机按需启停，完整备份和离线镜像包保持停用，具体保留策略见[升级与回滚说明](docs/platform-deployment.md#本机保留策略)。

## 功能与解决的问题

| 场景 | 提供的功能 |
|---|---|
| 校区和店铺分散，管理范围容易混淆 | 统一管理多个校区与店铺，店长、运营员按店授权，配送员按校区处理任务 |
| 一次想买多家店的餐品 | 搜索校区、店铺与餐品，独立店铺购物车，跨校区合并结算，各店分别履约 |
| 点餐后需要配送或自取 | 商家接单、备餐、派单，校区配送员抢单、取餐与送达，到店自取码核销 |
| 需要营销和日常经营工具 | 菜品与套餐、口味、每日配额、营业时间、活动价、店铺券、平台券和经营统计 |
| 订单出现问题，需要后续处理 | 取消订单、催单、图片举证、部分或整单退款、平台介入，以及收藏和评价 |
| 历史售后和异常任务不容易找到 | 用户售后、商家与平台的售后／退款／通知支持状态、日期、订单号筛选和加载更早记录；任务支持精确编号查询 |
| 店铺或校区搜索超过一页 | 用户端与工作台支持游标分页和加载更多；搜索结果可直接进入尚未加载的店铺 |
| 多个体验者需要独立账号 | 平台创建测试用户，首次改密，停用与重置后旧会话失效；本机试用模式关闭共享演示入口 |
| 订单久未推进或配送员离岗 | 分阶段服务时限、异常确认、停止接新单、未完成任务交接与紧急停用；超时不自动取消或退款 |
| 离线时错过订单变化 | 账号独立的站内消息、未读数、已读与离线补读，WebSocket用于提示刷新 |
| 模拟金额需要逐笔核对 | 事务内收支流水、历史期初快照、冻结日结及对账差异；没有真实付款或商户清算 |

跨校区合单时，各店的配送地址仍须属于该店所在校区；合并付款后，各店独立处理订单。

## 快速部署

以下步骤用于**首次本地源码构建与演示部署**。已有容器的日常启动见[常见问题与日常使用](#常见问题与日常使用)；已有业务数据或采用 CI 制品的环境，升级时先阅读[升级与回滚说明](docs/platform-deployment.md)。

### 1. 准备环境

- 安装 Git、PowerShell 7（命令为 `pwsh`）。Windows 自带的 Windows PowerShell 5.1 不适用于此启动脚本。
- 安装并启动 Docker Desktop，使用 **Linux 容器模式**，确保可用 `docker compose`。当前 CI 制品和 MySQL 补丁构建面向 **linux/amd64**（常见 Intel／AMD 64 位电脑），ARM 环境未验收。
- 首次构建时，Docker 构建器需能访问基础镜像、Maven／npm依赖和Oracle安全补丁下载源。下面的方式在 Docker 内构建应用，无需本机安装 Java、Maven 或 Node.js。

### 2. 下载并启动

打开 PowerShell 7 终端，依次执行：

```powershell
git clone https://github.com/W205614/CampusEats.git
cd CampusEats
pwsh -NoProfile -File ./scripts/start.ps1 -SkipVerify
```

脚本自动生成本机 `.env` 和随机初始密码，构建 Java、Web 和已安装安全补丁的 MySQL 镜像，初始化数据库与演示数据，并等待服务就绪。`-SkipVerify` 跳过本机 Maven 后端验证；省略该参数需另装 Java 21 和 Maven。该启动命令完成构建与健康等待，完整后端、浏览器和安全验证由 CI 执行。

启动结束后查看服务状态与初始密码：

```powershell
docker compose ps
Get-Content .local/demo-credentials.txt
```

四个服务均应显示 `healthy`。初始密码文件仅在本机保存，不要上传或分享。

### 3. 打开页面并登录

| 入口 | 地址 | 登录方式 |
|---|---|---|
| 用户点餐 | [http://localhost:18083/](http://localhost:18083/) | 点击「登录点餐」，选择一个演示用户，无需密码 |
| 平台／商家／配送工作台 | [http://localhost:18083/admin/](http://localhost:18083/admin/) | 使用下表账号，初始密码见 `.local/demo-credentials.txt` |

全新数据库会初始化两个校区、每校区两家店及以下员工账号：

| 角色 | 账号 |
|---|---|
| 平台管理员 | `admin` |
| 店长 | `manager1` ～ `manager4` |
| 店铺运营员 | `operator1` ～ `operator4` |
| 校区配送员 | `courier1`、`courier1b`、`courier2`、`courier2b` |

新建的店长、运营员和配送员共用文件中的初始密码，首次登录必须改密。已有账号保留原密码，修改 `.env` 或重新生成密码文件不会重置账号。

### 4. 体验第一笔订单

1. 先用 `admin` 登录工作台，在「校区与店铺」找到「默认店铺」，打开「营业配置」，确认营业时段，开启「接收新订单」并保存。全新数据库的店铺默认关闭接单。
2. 在用户端登录演示用户，选择「默认校区 → 默认店铺」，选餐加购；进入购物车，点击「选择此店」后「合并结算」。
3. 首次可选择「到店自取」，点击「计算报价」，提交订单后在订单页完成「整批模拟支付」。如选择配送，先添加与店铺同校区的收货地址。
4. 在工作台退出 `admin`，改用默认店铺的店长 `manager1` 登录并完成首次改密；进入「订单履约」，完成「接单备餐」和「备餐完成」。自取订单使用用户订单页的核销码完成核销；配送订单可派单或由本校区配送员抢单，再完成取餐、送达。

也可以用 `admin` 在工作台查看校区、店铺和员工归属。用户端与员工端会话独立，可在同一浏览器切换体验。三个演示用户各自隔离数据，但同一演示用户编号由所有访问者共用。

需要独立体验时，用平台账号进入「用户账号」创建测试用户，交付初始密码；用户在点餐端选择「独立账号登录」，首次改密后重新登录。忘记密码由平台重置，不提供开放注册或短信找回。

`.env` 中 `APP_MODE=demo` 保留演示入口；改为 `trial` 可在本机试用独立账号，关闭共享演示登录。空试用库只引导一个需要首次改密的平台账号，已有库不重置账号。默认仍绑定 `127.0.0.1`，两种模式都使用模拟资金。修改模式等运行配置后需重新创建对应容器，仅启动已有容器不会应用新的 `.env` 值，操作见[部署说明](docs/platform-deployment.md)。

## 常见问题与日常使用

| 遇到的问题 | 处理方式 |
|---|---|
| 找不到 `pwsh`，或脚本运行报版本相关错误 | 安装 PowerShell 7，使用上面的 `pwsh -NoProfile -File ...` 命令启动 |
| Docker 连接失败或构建下载失败 | 确认 Docker Desktop 已启动且处于 Linux 容器模式，并检查镜像源与依赖下载的网络连接 |
| `18083` 端口被占用 | 修改 `.env` 的 `WEB_PORT` 和 `ALLOWED_ORIGINS`，按[部署说明](docs/platform-deployment.md)应用配置，使用新端口访问 |
| 店铺休息中，无法下单 | 在工作台检查对应店铺的接单开关、营业时段和商品配额；新增店铺默认关闭接单 |
| 手机打不开页面 | 默认只监听本机 `127.0.0.1`，请先用部署电脑的浏览器体验 |
| 启动失败或页面无法访问 | 在项目根目录查看 `docker compose ps -a` 和下方日志；按需停止的容器需先启动 |
| `start.ps1` 提示当前环境已采用 CI 制品 | 日常启停使用下方命令；升级使用 `download-release.ps1`、`release.ps1`，按[CI 制品发布说明](docs/platform-deployment.md#已采用-ci-制品的日常环境)核对来源和依赖镜像 |
| 服务已启动，`ops-check.ps1` 提示无近期验证备份 | 本机备份按当前策略停用，该项会返回非零；逐项检查 `issues`，不要把其它服务、任务或数据异常当作同一原因 |

以下命令均在项目根目录执行：

```powershell
# 查看全部容器，包括已停止的服务
docker compose ps -a

# 查看最近的日志
docker compose logs --tail=100 server web

# 暂停服务，给数据库留出退出时间，保留数据
docker compose stop --timeout 60

# 再次启动已有容器，沿用原镜像和配置
docker compose start --wait --wait-timeout 300
```

以上是日常启停命令，不用于构建新版本或应用配置修改。数据库、Redis 和上传文件使用三个 Docker 持久卷保存。不要使用 `docker compose down -v` 停止日常环境，该命令会删除数据卷。

## 稳定性与验证

| 方面 | 已实现的约束 |
|---|---|
| 交易与金额 | 报价和提交使用上海业务时间；跨日旧报价需重新确认，结果不明时按原请求找回。模拟支付、退款与流水同事务落账，历史期初不伪造旧流水，日结只冻结已结束日期，对账差异只报告 |
| 履约与隐私 | 服务时限在阶段开始时保存快照；超时进入异常工作台，不自动取消或退款。配送员仅在履约期间获取必要联系方式，终态隐藏电话与详细地址 |
| 历史与搜索 | 身份、店铺及筛选范围绑定游标，失败保留已加载结果；历史记录约每15秒批量刷新，切换账号或店铺后旧请求不覆盖新状态。跨店搜索批量补充库存和活动 |
| 目录与举证 | 每店最多500个菜品和套餐（含停售项），每菜品最多20组口味，套餐最多50项。私有举证经鉴权读取，默认全局4、每账号2个并发，每账号每分钟120次 |
| 上传与限流 | 单实例共享上传空间账本、配额及磁盘余量检查；有容量上限的本地限流闸门与Redis计数共同约束请求，缓存淘汰不会重置本进程预算 |
| 镜像与依赖 | CI检查四服务系统包和后端Java运行依赖，任意等级的已知漏洞均阻断。MySQL在固定8.4.13镜像上安装经官方哈希及RPM签名校验的curl/libcurl补丁，与Java、Web一起进入CI制品 |

详细业务约束见[架构与接口](docs/platform-architecture.md)，配额、任务周期、运维接入及测量命令见[日常维护](docs/operations.md)，前端工具链兼容约束见[依赖说明](docs/frontend-security-review.md)。运维工具按需调用，不自动安装定时任务。

## 项目结构与阅读入口

```text
CampusEats/
├─ README.md              首次部署与第一笔订单
├─ pom.xml                Maven 多模块入口
├─ sky-common/            公共业务异常、摘要工具
├─ sky-pojo/              请求与响应契约
├─ sky-server/            Spring Boot 后端、数据库迁移与测试
├─ frontend/
│  ├─ admin/              平台、商家、配送工作台（Vue 3）
│  ├─ client/             用户端（uni-app，H5／微信小程序）
│  └─ contracts/          共享类型与 OpenAPI 契约
├─ compose.yaml          本地四服务编排
├─ Dockerfile            后端源码镜像
├─ deploy/               MySQL／Web 镜像、Nginx、Maven 配置与运维模板
├─ scripts/              启动、构建、验证和备份工具
├─ docs/                 现行指南、当前版本验证与演示截图
└─ .github/workflows/     GitHub Actions 验证流程
```

首次只需按本文完成部署；阅读源码时按[开发与源码阅读指南](docs/development.md)跟踪一笔订单。`.env` 和 `.local/` 保存受 Git 忽略的本机配置、凭据、验证记录及发布期间的临时材料，不属于共享源码。

根目录保留 Maven、Docker、编辑器和 Git 默认发现的配置与启动入口；部署配置统一放在 `deploy/`，Vite、TypeScript、应用配置继续由各模块维护。具体职责见[部署配置导航](deploy/README.md)，无需为集中存放而改变默认命令。

本机证据集中在 `.local/verification/`，目录由[当前版本记录](docs/verification/current.md)列明，不上传到GitHub。本机的 `.local/backups/LATEST.json` 和 `LATEST.txt` 是停用标记；明确执行发布时仍会生成临时恢复材料并更新指针，成功验证后须人工回收材料、恢复停用标记，发布脚本不会自动完成这些收尾。源码、当前镜像、业务卷、上传文件和必要配置继续保留。
