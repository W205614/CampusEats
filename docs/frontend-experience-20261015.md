# 前端入口与体验完善 · 2026-10-15

## 入口与登录

原根路径直接跳到 `/admin/`，且员工账户预填 `admin`。这属于默认入口和表单预设问题，不表示未登录用户已经获得管理员权限。

现在根路径跳到同源、同端口的 `/app/`，普通用户可先浏览校区、店铺和菜单，点击「登录点餐」选择演示账户。菜单和用户登录页提供工作人员入口；工作台登录与已登录界面均可返回点餐端，无需编辑网址。员工账户输入为空，成功登录后仍由真实角色决定进入工作台或配送台。

`campus-user` 和 `campus-admin` 继续独立保存。切换入口不会互相覆盖身份；服务端继续检查 API 角色与资源归属，页面入口不承担授权职责。

## 复核中修复的使用问题

- 用户旧 token 过期时，原先公开菜单请求会收到401并中断加载。现在仅对与服务端一致的匿名 GET 精确白名单清理旧用户会话后重试一次；私有读取及写请求不自动重播。
- 演示／微信重新登录不再携带旧 Authorization，避免旧 token 阻断新的认证请求。
- 迟到的旧请求401仅能清除自己对应的旧会话，不能清掉期间完成的新登录；不清理员工会话。
- 个人中心校验已保存的店铺偏好，失效时选择当前可访问的店铺，不向已不存在的店铺请求优惠券。领券、钱包与收藏加载完成后为空时提供明确说明。
- 商品图片原根路径被 uni-app H5 加上 `/app/` 前缀，误取SPA页面导致图片解码失败。H5现在将服务端根路径解析为当前站点或显式API地址的绝对URL，图片加载回归检查真实解码结果，而非只看HTTP 200。

## 界面完善

入口与工作台统一为深绿、浅纸色和系统中文字体。工作台登录提供明确关联的账户／密码标签、键盘提交与焦点状态；手机布局压缩品牌区域，工作台导航在顶部换行，避免挤压业务区域。点餐页保留校区、店铺、分类与营业筛选，H5登录使用原生链接支持键盘操作。小程序导航配色同步调整，H5工作台链接继续按平台条件编译。

设计使用用户指定的 design-taste-frontend skill，主要应用于公开入口与登录，业务屏幕保留操作密度。入口源码 lint 为0 FAIL／0 WARN；浏览器 inspector 实测390／768／1440，仍有关于四张图片、八个动效和海报焦点的画廊式规则不适用。没有将此记录为 inspector 全部通过，也没有为规则增加无业务意义的图片和动效。
