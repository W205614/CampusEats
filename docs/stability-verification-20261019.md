# 个人开发版稳定性改造验证 · 2026-10-19

## 改动及边界

保留单体、单实例和四容器部署。按店批量读取菜单目录、口味、套餐组成、动态库存和活动；冷热缓存均不再逐商品查询。商品图片和私有举证共用并发及字节预算，举证解码移出数据库事务，短事务锁定订单后检查数量并入库。明确失败时补偿文件；提交结果不明时保留文件供检查，避免删除可能已提交的举证。

支付与退款依赖内部 `PaymentGateway`，包含业务编号、整数分金额、币种及渠道回执，当前只有模拟实现。接口隔离不表示可以直接接入真实资金；异步状态、网络结果不明、回调验签与对账需后续规划。

修正当前合单接口指标，旧入口单独标记；指标采集失败后有效性为0，退款失败和积压值为-1，恢复后重新采样。增加上传拒绝和维护任务失败指标。

后台任务开启时每10分钟维护一次，每类最多200条，仅清理过期超过7天的会话、创建超过30天且已成功的Outbox。订单、资金记录、审计和业务图片不自动删除。V8仅新增索引，V1—V7未修改。

本地共验证25个不同的后端用例；修复或补充断言后的相关用例另行重跑，重跑不计为新增覆盖。

## 隔离升级和容器验证

先备份原日常数据，使用独立MySQL容器验证全表数量、校验和、文件哈希和数据约束。再在 `campuseats-stability-acceptance` 项目、独立卷和28083端口导入V7备份及上传文件，将整套服务停止后调用新版启动脚本。

验证升级前备份与独立恢复通过后才启动应用，Flyway仅执行V8；四容器健康，历史记录指纹一致。完成只读冒烟、隔离举证上传／读取、匿名访问拒绝及运维检查。日常业务库不用于写入式验收，验收数据不回灌日常库。

备份入口会恢复调用前的服务运行状态；发布入口在备份期间保持业务写入暂停，避免备份与升级之间重新开放写入。成功标记只在恢复验证及状态恢复成功后生成。运维检查不自动创建备份、清理文件或恢复退款任务。

## 发布与恢复材料

原环境快照、镜像ID、定向测试及构建日志保存在受忽略保护的 `.local/stability-20261019/`；改造前备份为 `.local/backups/20261019-before-stability/`。发布前后备份位于 `.local/backups/` 的独立时间目录，验证成功的备份包含 `verified.json`。

旧日常镜像保留 `rollback-stability-20261019` 标签。最终版本从提交源码构建，后端及Web镜像通过 `org.opencontainers.image.revision` 标记提交SHA；部署保留原MySQL、Redis及上传卷。最终远程完整验证以交付提交对应的GitHub Actions结果为准。

没有安装系统定时任务、异地备份、外部告警、高可用或真实支付退款；没有验证生产峰值容量、长时间稳定性和微信真机。只读运行检查和有限并发用例不能替代这些验证。
