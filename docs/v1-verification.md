# v1 实施与验收记录

本次把升级前的课程实现留在 `legacy/`，重建了仍由三个 Maven 模块组成的 Java 单体，以及管理端和 uni-app 用户端源码。运行环境使用独立 `campuseats-v1` 卷；原项目卷与其他项目容器未删除。

## 已实现

- Java 21 / Spring Boot 4.1.1 / MyBatis 4.0.0；Hikari、Spring Security、Argon2id、数据库可撤销会话、Jackson 3、springdoc。
- Flyway 空库建表、增量迁移、utf8mb4；旧库必须显式基线；重复数据使迁移失败，历史地址标记来源，不制造配额流水。
- 用户购物车行锁和版本协议；同用户请求键唯一；服务端重新计价、报价摘要、地址和商品快照。
- 每日菜品配额、套餐组成合并扣减、预占转消耗、接单前释放、跨午夜按原日期释放。
- 营业时段、人工关店、校园楼栋/房间、可调配送与包装费用、员工角色、派单和配送归属。
- 模拟支付和退款，任务租约、失败重试/人工处理、事务 Outbox、一次性 WebSocket 票据和断线查询。
- 菜单批量口味、订单分页批量明细、统计按日期聚合、聚合导出；缓存有界回源和精准失效。
- 图片解码重编码、分页/数量校验、账户/IP/用户限流、统一状态码和 requestId。
- Vue/TypeScript 管理端所有业务入口；同一套 uni-app 页面构建 H5 和微信小程序；生成的 OpenAPI 类型用于两端核心实体。
- 源码构建镜像、就绪/存活、Prometheus 指标、CI、备份与独立恢复脚本。

## 验证方法与证据

Java 测试使用 Testcontainers 创建 MySQL 8.4 和 Redis 7.4；使用真实事务、唯一约束、条件 SQL 和竞争线程，不以 Mock Mapper 代替交易数据库。测试容器不使用演示数据库。测试连接池等待上限 15 秒，部署上限 3 秒；后者过载时返回 503，不把排队无上限当成容量。

核心测试覆盖 20 同键竞争、不同键竞争购物车、50 用户竞争 10 份、接单/取消竞争、重复释放、套餐回滚、跨午夜、支付超时、重试租约、数据库迁移与权限。大于 JavaScript 安全整数的 ID 通过 HTTP 保持字符串；导出验证真实 XLSX 内容；Redis 暂停时订单和退款仍然持久化。新增缓存测试验证失效任务与商品事务一同提交、回滚不留下事件。

最终交易实现回归：`mvn -B -ntp verify` 共35项，33项交易/协议测试及2项迁移测试，失败、错误、跳过均为0（`verify-optimized.log`）。50用户竞争10份分别验证首次初始化日期与已配置日期。配额锁移到事务末尾缩短锁持有时间；常规扣减走条件UPDATE，仅首次初始化/不足分支执行独占锁upsert，仍在同一事务内，售罄会回滚此前的订单、购物车、审计与事件。

浏览器使用 Chromium / Playwright，执行 H5 创建地址、选餐、报价、提交和模拟支付，管理端接单、派单、配送、送达，以及用户取消退款。另一场景让服务器真实创建订单后丢弃 HTTP 响应，再用原请求键恢复并核对只有一条订单。测试使用独立浏览器上下文，不保存含会话令牌的 HAR 或 trace。

初版3条浏览器流程通过（`e2e-release.log`）；两端类型检查、管理端/H5/小程序源码构建通过（`build-web-release.log`，本机重复构建见`frontend-final.log`）。结算在打开确认框前置忙，结果恢复也拒绝并行点击；丢失响应测试同时验证快速双击后仍可找回唯一订单。一次复验曾提前点击自定义uni-button的禁用按钮导致脚本失败；已等待其disabled属性消失后再操作，没有用固定睡眠掩盖竞态。

交付前扩展为9条真实页面流程，最终全部通过，49.5秒（`e2e-final-delivery.log`）：

- H5下单模拟支付，管理端接单、派单、开始配送、送达，H5查询送达。
- 快速双击提交且丢失真实响应后，用原请求键恢复唯一订单。
- H5取消已支付订单，持久化退款完成后显示已退款。
- 管理端新增分类、带口味菜品、上传图片、编辑价格、创建套餐、停用和删除；H5核对实际保存的名称、价格和口味。伪装PNG上传被400拒绝，真实PNG解码重编码后可显示。
- 楼栋启停、当日配额售罄、默认配额调整、关店/开店；H5售罄和关店禁止选餐。使用独立菜品验证配额，结束后还原营业规则并清理菜品。
- 地址新增、编辑、设默认、删除；下单取消后再来一单、购物车增减与清空；删除地址后历史订单仍保留联系人和房间快照。
- 运营员和配送员分别通过页面创建、登录、强制改密、重新登录；隐藏管理入口，直接访问管理URL实际返回403，禁用后旧会话回到登录页。
- 30天统计、实际下载XLSX，审计及退款/通知待处理列表返回与页面一致。列表为空是合法结果，不要求伪造失败任务。

扩展测试发现并修复Element Plus确认框未设置中文，以及配额列表的字符串数量与数字输入控件不兼容（`Number(row.total)`）。其他失败属于脚本定位/等待和数据前提：uni-app占位提示不是原生placeholder、开关实际点击外层、先停用再删除、明确选择商品分类、不在页面加载前判断行是否存在。原始失败日志保留；没有降低业务断言或使用固定睡眠。最终源码镜像重建见`build-web-delivery.log`，最新WebSocket验证见`websocket-delivery.log`。

WebSocket真实HTTP升级测试（`scripts/check-websocket.mjs`）验证合法Origin及票据可连接、异源/伪造/重放被拒绝、退出后连接关闭；最终结果见`websocket-optimized.log`。

实际容器演练（`recovery-optimized.log`）：先注入持久化的PROCESSING过期租约，再更换Java进程，退款及通知任务恢复成功；Redis停止期间菜单回源、下单、支付、取消和退款可完成，新票据返回503；MySQL停止期间就绪检查及业务请求返回503，恢复后容器重新健康。这是模拟网关和明确租约故障注入，未验证真实外部资金副作用。

备份`.local/backups/20261007-complete`已在独立MySQL容器恢复：13订单、13明细、3用户、6退款任务、46Outbox、1配额记录；16张业务表校验值和上传文件哈希一致，孤立明细/异常配额均为0。它是当时的数据快照，后续演练新增订单不属于该备份。

本机演示已由验收流程开启全天营业；全新数据库默认仍为人工关店。

## 容量测试

机器：AMD Ryzen 5 6600H，6 核 / 12 线程，约 31.2 GiB 内存；Windows + Docker Desktop Linux Engine。测试时其他 Tianji 容器仍在运行。本项目限制 MySQL 768 MiB、Java 768 MiB、Redis 160 MiB、Nginx 128 MiB；Hikari 最多 20 连接。

数据：100 个独立用户、10,000 个历史订单、50,000 条明细；订单查询按各自用户过滤。菜单为演示菜单；下单负载每个用户每 10 次循环执行一次单菜品下单、同键重试和取消，其余循环查询菜单与订单。不是全写、多 SKU、真实微信或真实支付负载。20并发预热30秒后，20/100并发各2分钟，50并发持续10分钟。连接池最小/最大均20；JRE镜像Temurin21.0.12.1，Docker29.8、12CPU、约15.2GiB可用内存。

容量结果与具体镜像、Docker资源、请求数、错误计数、P95/P99、完整性检查保存在本机`.local/loadtest/`，密钥和测试令牌不提交Git。旧轮次留在`.local/evidence/load-baseline/`、`load-pre-warmup/`及`load-before-lock-scope/`。其中最后一个旧轮次50并发P95为58/75/572ms，1/72,875非预期错误（约0.00137%）；20并发下单P95为1218ms未达标。原始失败记录保留，不用日志四舍五入后的0.00%掩盖非零错误。锁范围优化的旧轮次初段曾同时进行前端安装/构建；最终优化轮次开始前这些检查已结束，其他Tianji容器仍持续运行，属于共享开发机观测，不能把单次差值全部归因于某项优化。

本次实际执行计划：用户列表使用`ix_order_user_time`反向索引查找，返回20行；管理端无筛选列表曾扫描约11,275行再排序，新增V4时间索引后使用`ix_order_time`反向扫描只取20行，最终采样约0.055ms（单次Explain Analyze）。原始计划在`.local/loadtest/explain.txt`，不承诺任意生产分布都选同一索引。

## 依赖安全与边界

管理端 npm audit 无已知漏洞。用户端可兼容的修复已通过依赖 overrides 锁定；当前仍有 7 项高危构建依赖告警，根源为 braces 的 [GHSA-vfj7-8cjw-p6xm](https://github.com/advisories/GHSA-vfj7-8cjw-p6xm)。公告当前无修复版本。它们用于本机可信源码的构建/文件匹配，生产镜像由 Nginx 提供静态文件，不运行该 Node 开发服务器。例外限定包和公告，禁止新增/critical 漏洞绕过，2026-11-07 到期必须复核。这是有期限的风险接受，并不代表依赖扫描全部清零或完成渗透测试。

uni-app 的 H5 Vue fork 与编译器必须匹配。直接把所有编译器覆盖为上游 Vue 3.5 会造成实际导航异常；已经保留 DCloud 对应的 3.4.21 编译器，并验证 H5 和小程序构建。开发服务器绑定 loopback。

本机找到微信开发者工具，但 CLI 提示服务端口关闭，自动工具验收未完成。没有用户的真实 AppID、合法 HTTPS 请求域名和微信登录配置，因此开发者工具预览、真机和真实微信登录仍须按部署文档单独记录。编译成功和 H5 成功不能代替这些结果。真实支付与退款明确不在此次交付范围。
