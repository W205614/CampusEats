# 四角色真实操作验收 · 2026-10-19

本轮按用户、商家、配送员和平台管理员完成页面操作与异常恢复验收。保持单体、单实例与四服务部署；支付、退款均使用模拟实现，没有真实资金交易。

## 环境与证据边界

日常环境为 `campuseats-v1`、18083端口。验收前使用 `safe-backup.ps1` 暂停写入并完成独立恢复检查，备份在 `.local/backups/20261019-before-role-uat/`，随后恢复原运行状态。

全部写入式验收在 `campuseats-role-uat`、28085端口及独立MySQL／Redis／上传卷进行，测试数据不复制到日常数据库。后台模拟退款任务保持启用。

两条完整旅程由API准备独立校区、店铺、商品、配额、活动、优惠券与员工；登录、员工首次改密、加购、地址、领券、报价、结算、模拟支付、接单备餐、配送／核销、举证与售后均在真实页面操作。API读取核对金额与最终状态，刻意越权请求单独检查拒绝结果。

另两项异常旅程通过API准备已付款且备餐完成的配送订单，集中操作取消／撤销／申诉、旧页面抢单、平台改派、实际交接确认及异常取消退款。它们验证异常节点，不重复声称其准备阶段属于页面操作。

六项传输异常浏览器检查使用API夹具，模拟401、延迟、报价失败及时间边界，不写真实业务数据。

## 四角色操作结果

| 角色 | 本轮覆盖 |
|---|---|
| 用户 | 登录、跨校区选店、独立购物车、配送地址、领券、混合履约合单与模拟支付；取消／撤销、举证、连续部分退款、剩余整单退款、评价及账号切换 |
| 商家 | 首次改密、授权店铺隔离、接单备餐、发布抢单、自取码核销、查看私有举证、同意退款、拒绝后转平台介入 |
| 配送员 | 校区任务隔离、抢单池不暴露完整收货信息、抢单／取餐／送达；待取消旧任务点击被拒绝，撤销取消后任务恢复；改派后原配送员失去操作权限 |
| 平台管理员 | 售后介入裁决、配送中改派与交接确认、保留已取餐状态、异常取消与模拟退款；不影响其他店铺子订单 |

混合履约旅程还核对优惠分摊的分位尾差、连续退款的数量／金额、费用退款、优惠券保持已使用，以及另一子订单的快照不变。

## 发现与修复

| 问题 | 修复与复验 |
|---|---|
| 评价成功后仍显示评价入口，重复提交只得到“数据冲突，请刷新后重试” | 订单详情／列表批量返回`reviewed`，页面显示“已评价”；重复与并发请求返回`409 REVIEW_EXISTS`，旧页面收到该结果后关闭弹窗并刷新 |
| 用户申请取消后配送任务仍可抢，但取餐被取消申请拦住 | 待处理／介入中的取消申请退出抢单池；抢单在订单锁内再次检查，防止旧页面竞态；撤销或拒绝后恢复 |
| 报价返回前修改选项／备注，旧响应仍恢复提交入口；重报价失败保留旧价格 | 输入失效时递增请求序号，丢弃旧报价；重新报价先清空旧结果，失败后不显示过期提交入口 |
| 账号失效或切换后，缓存的购物车、订单／取餐码可能残留，旧请求还可能覆盖新页面 | 会话变化同步清空私有状态，异步结果和加载标记仅允许原会话写回；跨等待的提交、恢复、上传等同样检查会话 |
| 刚提交售后就显示平台介入，但后端要求拒绝或超过48小时 | 页面按既有规则显示入口并给出等待说明；上海无偏移时间和显式ISO时区均核对48小时边界 |

## 发布与清理边界

验收通过后，以本次提交源码重建日常镜像。`scripts/start.ps1 -SkipVerify`保留旧镜像，构建成功后暂停写入、备份并独立恢复检查，再使用原持久卷更新容器。发布后的健康、镜像revision、业务表校验和及只读冒烟结果保存在上述本地证据目录。

清理只面向本项目的临时验收容器和明确冗余的验收镜像；先记录所有容器引用并归档待删除镜像，保留SHA-256与恢复材料。保留日常数据卷、历史备份、回滚镜像及其他项目资源，不执行全局prune。最终交付以实际健康检查、清理记录和对应提交CI结论为准。

这些场景不能推出生产容量、长期可用性或真实支付成功率。
