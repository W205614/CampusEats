# 2026-10-21 历史刷新与图片空间检查

本轮保持单实例四服务、模拟支付与退款，不新增数据库迁移、外部告警或定时任务。仅验证修改及直接影响的功能；完整回归和安全扫描由最终提交的 GitHub Actions 执行。

## 改进与效率证据

- 订单、用户结算单、售后、退款和通知任务沿用原路径和数组响应，新增可选 `limit`，默认100、范围1—1000；非法值返回400，原用户／店铺／配送校区权限不变。
- 单个列表仍刷新全部已加载记录，按最多1000条批量读取。共用读取工具的确定性验证中，10页只发1次列表请求，11页发2次；新记录、旧记录状态变化和筛选移除均保留原有语义。这是请求与重复查询次数优化，不是响应数据量或生产容量结论。
- 图片空间账本同时计入公开、私有和临时文件，写入／移动／回滚与校准共用锁。首次、60秒到期后使用、距容量上限不足5MiB、公开文件数达到9999或账本不确定时重新扫描；每次准入和发布仍检查真实磁盘剩余空间。
- 在非临界区且60秒内，12次正常公开／私有混合上传及回滚仅执行1次完整扫描。测试还核对账本与实际文件字节数及公开数量一致。单实例独占管理上传卷，容器外变动通过按需校准发现，恢复与手工改文件需停写。

## 定向验证

14个不同后端用例通过：2个历史查询真实MySQL集成用例、10个图片空间单元用例、2个既有举证授权及并发／数据库失败集成用例。新增历史夹具超过1100条，验证1000条批量与连续游标、默认和非法参数、用户／店铺／配送校区隔离；明细与举证保持批量查询。图片验证包含10000公开文件上限、启动与重启、可控60秒时钟、并发临时字节、回滚、重复关闭、编码和发布失败。

24个不同前端及页面用例通过：11个历史／恢复浏览器用例、11个实际请求封装的VM用例、1个批量读取工具用例、1个真实图片页面链路。用户及商家订单分页在最终隔离Web镜像上复验，历史保留、轮询及手动回到第一页行为一致。两端类型检查和生产构建通过；候选Web源码镜像另完成H5与微信小程序构建，活接口生成OpenAPI及TypeScript快照。

真实图片链路使用独立项目 `campuseats-refresh-storage-20261021`、端口28087及独立MySQL／Redis／上传卷：API准备店长和订单，店长通过商品编辑页面连续上传并保存图片，用户通过售后页面上传举证并提交，商家通过售后页面预览。验证所有者与本店店长可读、其他用户返回404隐藏订单存在性、公开私有路径返回401。举证数据库失败后的文件处理由真实MySQL集成用例验证，不将API准备步骤称为页面验收。

验证过程中修正两处夹具预期和一处选择器歧义；还发现并修复当前账号失效提示被旧响应保护逻辑抑制的回归，仅复验失败及关联路径。管理端请求封装增加请求令牌比对，旧401不清除新登录，不自动重放请求。失败日志保留，不把首次失败记为通过。
